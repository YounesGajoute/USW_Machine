# Frontend screen map

Last generated audit date: **2026-10-22**. Evidence status: **CONFIRMED** static routes/components; access under deployed settings and runtime display **UNVERIFIED**.

## Purpose and scope

Locate all registered screens, nested settings panels and important operator controls. All six screen route cases are registered in `frontend/src/App.tsx:L164-L180` inside HashRouter. URLs therefore use hashes, for example `/#/settings/vision`. Settings section IDs are path parameters; inner tabs are local state, not independent router URLs. Unknown paths redirect to `/`.

## History filter limitation

`HistoryView.buildFilters` includes only `limit`, `offset` and the current handler overrides (`frontend/src/components/history/HistoryView.tsx:L80-L99`). Pagination supplies only a new offset (`frontend/src/components/history/HistoryView.tsx:L108-L112`), so it drops an existing search/date query while the filter controls retain their displayed values. Changing date and search also replaces the other query field. This source-defined inconsistency is **CONFIRMED**; no browser reproduction was run. ErrorHistoryView separately includes its current filter values in every query (`frontend/src/components/error-history/ErrorHistoryView.tsx:L70-L97`).
