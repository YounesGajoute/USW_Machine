# Testing and validation

Last audited: 2026-10-22. Status: test source and selection audited; no application import, build, test, probe, capture, firmware flash or machine action was executed. Purpose: let a maintainer select relevant validation without accidentally running the machine or reading production data. Scope: declared package scripts, backend/frontend tests, pick-and-place simulators, centring firmware tooling, device diagnostics and soak utilities. Passing results are intentionally not claimed.

## What this audit validated

The documentation audit used filesystem metadata, source-text reading, static symbol/import/route extraction and comparison of duplicate source trees. These actions do not test runtime scheduling, device responses, native modules, compilation, network binding, motion limits or interlocks. No production database, `.env`, capture, historical execution log, existing explanatory document or preserved API manifest was used as behavioral evidence.

Source parsing can identify missing files, dead code, mismatched command names, likely races and side-effecting imports. It cannot prove a hardware safety response, a successful upgrade, or end-to-end operation. The [backend module manifest](manifests/backend-modules.json) records each backend file, symbols, direct imports, direct test links and test declarations. Empty extracted side-effect arrays do not prove absence of transitive, computed, native or dynamically dispatched effects.
